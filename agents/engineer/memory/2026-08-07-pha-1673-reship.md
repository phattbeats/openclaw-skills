## The buildPaperclipApiFetch wrapper

```ts
export function buildPaperclipApiFetch(ctx: AdapterExecutionContext): typeof fetch {
  const paperclipApiUrl = resolvePaperclipApiUrlOverride(ctx.config.paperclipApiUrl);
  const runId = ctx.runId;
  return (input, init) => {
    const targetUrl = input instanceof URL ? input : new URL(typeof input === "string" ? input : (input as Request).url);
    if (!paperclipApiOriginMatches(targetUrl, paperclipApiUrl)) {
      return fetch(input, init);          // 3rd-party — pass through
    }
    if (initHasHeader(init, PAPERCLIP_RUN_ID_HEADER)) {
      return fetch(input, init);          // explicit header — preserve
    }
    return fetch(input, withInjectedRunIdHeader(init, runId));  // auto-inject
  };
}
```

Design choice: returns a `fetch`-shaped function (not a higher-order wrapper) so call sites stay one-liner and the spy/stub in tests is straightforward. Mirrors the hermes bridge pattern (`packages/adapters/hermes/skills/paperclip-task-bridge/paperclip-task.mjs:142`) and the adapter-utils sandbox-callback bridge (`packages/adapter-utils/src/execution-target.ts:1808`).

## Lesser-known Paperclip validator: `in_review` requires a real review path

First time I hit this. PATCH `{"status": "in_review"}` from an agent returns:

```
invalid_issue_disposition: Agent-authored updates that move an issue to in_review must include a real review path.
```

Required to include one of:
1. `pending_issue_thread_interaction` — pending request_confirmation / ask_user_questions / suggest_tasks
2. `linked_pending_approval` — pending approval record
3. `human_assignee_user_id` — assign a human via `assigneeUserId`
4. `typed_execution_state_current_participant` — typed executionState
5. `scheduled_issue_monitor` — schedule an issue monitor

I used option 1 (request_confirmation with `requestedResolverPolicy: board_only`). Worked.

**Workflow:** before transitioning an agent-authored issue to `in_review`, create one of these review paths FIRST. Then retry the PATCH. The validator is on the side of "don't leave in_review without forward motion."
